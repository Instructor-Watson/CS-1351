# Personal Project Part 2 Rubric — 100 points

| Criterion | Weight | Excellent (100%) | Proficient (60%) | Needs Improvement (30%) |
|---|---:|---|---|---|
| Functional Expanded Project | 25% | Functional workflow fully implements the Part 1 expansion with all required features working from a clean start. The project runs without major errors and demonstrates robust behavior across typical use cases. | Most core features work and the project runs, but there may be minor errors or edge cases that do not break major functionality. | Major parts of the workflow fail or are nonfunctional; the project cannot demonstrate the requested expanded capabilities. |
| Presentation Content | 15% | The presentation clearly explains design changes, demonstrates the complete workflow, and identifies key Java concepts used. | The presentation covers most required elements, but one aspect of design, workflow, or concepts is incomplete or not fully demonstrated. | Insufficient design explanation or demonstration of the workflow; several required elements are missing or unclear. |
| Presentation Delivery | 15% | Delivery follows a clear sequence, stays within the 5–10 minute range, and is easy to understand. | Organization, timing, or clarity needs improvement, but the audience can still follow the presentation. | The presentation is disorganized, overly rushed, or drawn out, making it hard to understand. |
| Readability | 10% | Code readability is enhanced by consistent structure, clear naming, and logical formatting. | Some parts are readable, but there is noticeable disorganization or unclear naming in places. | Code is very hard to read due to poor structure, naming, or formatting. |
| Meaningful Comments | 10% | Comments explain non-obvious intent and reasoning behind complex decisions or tricky sections. | Comments exist but do not sufficiently clarify the non-obvious parts of the code. | No meaningful comments explain non-obvious behavior or decisions. |
| Collection Processing | 10% | An array or ArrayList stores data effectively and supports meaningful project operations, such as searching, updating, or iterating. | Collection use is partial or incomplete, limiting the project's data-handling capabilities. | No meaningful collection use; data storage is missing or inappropriate for the tasks. |
| String Manipulation | 5% | Meaningfully changes, searches, formats, or analyzes text. | String manipulation is present but incomplete. | String manipulation is not used. |
| Input Validation | 10% | Input validation uses a loop to reprompt until valid input is received and explains what is wrong when input is invalid. | The loop or messaging partially works, or validation is incomplete, causing user confusion. | No effective input validation or loop-based retry mechanism; invalid input is not properly handled. |
